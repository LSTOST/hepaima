# 题目在代码里的位置 + 为何服务器 seed 后前端还是旧题

## 一、代码里题目定义在哪

| 题型 | 文件 | 变量/函数 | 说明 |
|------|------|-----------|------|
| **通用版**（1–7 量表） | `src/lib/questions-universal.ts` | `universalQuestions` | 数组，约 30 题 |
| **分阶段**（暧昧/热恋/稳定期） | `src/lib/questions.ts` | `ALL_QUESTIONS` + `getQuestionsByStage(stage)` | 暧昧 28 + 热恋 35 + 稳定 40 题 |

要看「代码里有没有新题目」：

- 打开上述两个文件，看数组里题目的条数、`text`、`id` 等是否和你预期一致。
- 通用版：搜 `universalQuestions`，数一数对象个数。
- 分阶段：搜 `ALL_QUESTIONS` 里各题目的 `text`，或看 `getQuestionsByStage` 的注释（暧昧 28 / 热恋 35 / 稳定 40）。

---

## 二、为什么在服务器跑 seed 后前端还是旧题

**seed 脚本用的是「当前机器上的代码」写库。**

- 在**服务器**上执行 `pnpm seed` → 用的是**服务器上的** `questions.ts` / `questions-universal.ts`。
- 如果你只在**本地**改了题目、没有把新代码部署到服务器，那服务器上的代码还是旧的 → seed 会把**旧题目**写进数据库 → 前端请求的是服务器 API（读数据库），所以看到的还是旧题。

正确顺序应是：**先让服务器拿到最新代码，再在服务器跑 seed。**

---

## 三、正确更新流程（代码里有新题目时）

1. **本地**改好题目（`questions-universal.ts` 和/或 `questions.ts`），提交并 push。
2. **服务器**拉最新代码并安装依赖（若用部署脚本则一起做）：
   ```bash
   cd /www/wwwroot/hepaima.kyx123.com
   git fetch origin && git reset --hard origin/main
   pnpm install --frozen-lockfile
   ```
3. **服务器**跑 seed，用当前（已更新）的代码写库：
   ```bash
   pnpm seed
   ```
4. 若 Next 是单独起的（如 PM2），一般不用重启（题目来自 DB）；若改动了会参与构建的代码，再 `pnpm build && pm2 restart hepaima`。

这样数据库里的题目就和「代码里的新题目」一致，前端也会显示新题。

---

## 四、如何确认服务器上的代码是否已更新

在服务器上直接看题目文件内容是否和本地一致，例如：

```bash
# 通用版题目数量（约 30）
grep -c "id:.*category:" /www/wwwroot/hepaima.kyx123.com/src/lib/questions-universal.ts

# 分阶段题目总数（约 103）
grep -c "id:.*stage:" /www/wwwroot/hepaima.kyx123.com/src/lib/questions.ts
```

或打开 `src/lib/questions-universal.ts`、`src/lib/questions.ts` 看具体题目文案是否为新版。若这里还是旧的，说明部署没更新到这两份文件，需要再走一遍部署流程（git pull / 部署脚本）后再跑 seed。
